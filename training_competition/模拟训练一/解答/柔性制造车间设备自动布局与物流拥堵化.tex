	\begin{abstract}
		车间设备布局优化是提高车间运行效率的关键。本文依次建立物流长度快速评估模型、带多约束的全局布局优化模型、改进网格拥堵评估模型与任务波动下多目标稳健布局模型，并通过岭回归、7 折交叉验证、带约束组合优化、Big‑M 法、图网络建模、BFS 最短路径求解、Logit 路径选择、拉丁超立方抽样、CVaR 条件风险度量、多目标加权优化方法进行求解，为制造车间提高运行效率提供具体规划方案。
		
		针对柔性车间工艺切换频繁、易发生物流拥堵、任务波动下布局适应性不足的问题，本文构建物流长度快速评估、多约束全局布局优化、网格拥堵评估以及任务波动下多目标稳健布局系列模型。利用岭回归实现真实物流长度快速估算，通过 Big‑M 法、图网络、BFS 路径求解、CVaR 风险度量等方法完成模型求解。算例表明：快速评估模型相比传统 RBE 指标预测精度显著提升；全局优化可缩短搬运距离；改进拥堵模型能够识别拥堵热点；稳健布局以少量运输效率牺牲换取拥堵风险与改造成本下降，可为柔性车间设备布局提供规划参考。
			
		\textbf{关键词：}车间布局；物流长度；曼哈顿距离；矩形包络
	\end{abstract}
	
	\section{问题重述}
	1.1 问题背景
	
	随着离散制造业向柔性化、数字化和智能化发展，车间设备布局成为车间运行效率快慢的关键。柔性制造车间具有产品品种多、批量小、工艺路线品频繁切换的特点。设备布局直接决定AGV总运输距离、局部拥堵程度和生产节拍。不合理的设备布局会引发物流运输交叉、局部通道过载，降低整个车间的运行效率。
	因此，针对车间设备布局的优化问题，本文将为车间提供车间设备优化模型，提高车间运行效率。
	
	1.2问题要求
	
	该车间为矩形车间，布置多台不同尺寸的矩形设备，每台设备带有若干物流接口；多个接口组成物流任务组，对应零件多设备流转的物料运输需求.AGV仅沿水平、竖直方向行进，运输距离采用曼哈顿距离计算。设备布局优化属于复杂组合优化问题，工程上一般先完成全局布局，再做局部微调得到可落地方案。
	
	布局优化需要兼顾四项目标：物料搬运总距离尽量小；设备不过度局部聚集；AGV交通流网格分布均衡，规避拥堵热点；面对生产任务强度波动，布局具备稳定性与适应性。车间将整体划分为规则网格，通过网格内设备占用率约束避免设备过度聚集；物流任务组给出RBE矩形包络估计长度）作为快速距离估算指标，但该指标在接口数量多、空间分布复杂时，和真实最短连通长度RML偏差较大。
	
	已知矩形车间坐标范围\([0,W]\times[0,H]\)，设备方向固定不可旋转，仅改变设备左下角坐标，设备物流接口绝对坐标随设备位置平移；给定物流任务组数据（接口、RBE、RML、日均搬运批次）、车间与设备基础参数（设备尺寸、网格划分、网格最大占用率阈值等）。需要完成 四个建模问题：
	
	问题一：快速物流长度评估模型
	
	RBE 计算简便，但多接口任务组估计误差明显。利用接口数量、坐标分散程度、包络矩形形状等信息，构建模型对真实最短连通长度 RML 做估计：
	
	1. 建立快速评估模型估计 RML；
	
	2. 设计误差评价指标，对比该模型与直接使用 RBE 估计的精度；

	3. 分析模型在不同接口数量、不同空间形态任务组上的适用效果；
	
	4. 使用该模型计算当前布局下车间日均加权搬运距离。
	
	问题二：车间设备全局布局优化模型
	
	以各设备左下角坐标作为决策变量，构建全局布局优化模型：
	
	约束条件：①设备整体落在车间边界之内；②全部网格设备占用率不超过给定阈值；③处理设备实体互相重叠问题；
	
	优化目标：最小化日均加权搬运距离。
	
	基于附件数据求解优化模型，输出：
	
	(a) 优化后目标函数值，对比现有布局的改善比例；
	(b) 每台设备优化后的左下角坐标；
	(c) 车间设备布局可视化结果；
	(d) 各网格设备占用率分布，校验全部网格满足占用率约束。
	
	若算法存在随机性，需要给出参数设置，多次独立运行分析结果稳定性。
	
	问题三:AGV网格拥堵评估模型
	
	题目给出矩形扩散式物流密度模型：任务组物流量在接口最小外接矩形内均匀扩散，依靠重叠面积比例分配每个网格的物流量贡献，累加得到网格物流密度。完成以下任务：
	
	1. 分析该矩形扩散物流密度模型存在的主要缺陷；
	
	2. 改进得到新的网格拥堵评估模型，需要体现AGV只能横纵移动、任务强度差异、路径不唯一、设备阻碍通行空间等现实因素；允许采用近似、采样、概率路由等方法，同时说明计算复杂度与近似误差来源；
	
	3. 将改进模型应用于问题2得到的布局，计算各个网格拥堵强度；
	
	4. 绘制网格拥堵热力图，定位高拥堵区域，分析拥堵产生原因。
	
	问题四：任务强度波动下多目标稳健布局模型
	
	每个物流任务组实际搬运批次在区间\([0.85f_k,1.15f_k]\)独立波动，\(f_k\)为基准日均搬运批次。需要同时兼顾：搬运距离短、降低网格最大拥堵压力、控制设备移动距离以减少改造费用，同时保留车间边界、网格占用率等基础约束，构建多目标稳健布局模型。给出可工程落地的推荐布局，并与问题2的布局结果对比分析：
	
	(a) 基准任务强度下，推荐布局在运输效率、拥堵水平、设备调整成本三方面的性能；
	
	(b) 任务强度随机 / 不利波动条件下，该布局是否依旧保持稳定性能；
	
	(c) 分析多个优化目标之间的权衡冲突关系；
	
	(d) 若只能改造部分设备，模型能否输出设备调整优先级顺序。
	\section{问题分析}

	本题的研究对象是柔性车间设备布局，研究内容为车间设备优化和设备布局的优化。它实际上是一个组合优化问题\cite{tian2026slp}，依次构成工具构建、基础优化、性能评价与改进优化的完整研究链条。
	
	\subsection{问题一分析}
	
	对于问题一，在车间设备布局优化问题中，物流搬运距离是评估布局方案优劣的核心指标。若是直接求解真实物流长度RML，需要计算任务组内全部物流接口之间的搬运路径，计算量大，难以在布局迭代优化过程中实现快速评估。因此工程实践中常采用包络矩形边长RBE作为近似估计量，该方法仅通过包围全部物流接口的最小外接矩形周长进行估算，具备计算简便、耗时短的优势。
	
	然而RBE方法存在明显缺陷：该指标仅利用外接矩形轮廓信息，没有考虑任务组内物流接口的总数量、接口在矩形内部的空间分布离散程度，以及包络矩形自身的几何形态。当接口分布不均匀、接口数量较多，或是外接矩形形状狭长时，RBE对真实物流长度RML的估计偏差会显著增大，估计精度无法满足工程要求。
	本题需要建立一套快速物流长度评估模型，以RBE的估计结果进行校准，得到精度更高的RML预测值，同时保持快速计算的特性。
	
	模型建立完成后，需要构造合理的误差评价指标，将新建模型与直接采用 RBE 估计的基准方法进行精度对比，验证模型改进效果。随后通过分组实验，分析模型在不同接口数量、不同空间几何形态任务组上的适用范围与局限性。最后利用该预测模型计算当前布局下车间日均加权搬运距离D，为后续全局布局优化提供目标参数。
	
	\subsection{问题二分析}
	
	对于问题二，本题基于问题一建立的快速物流长度评估模型，开展车间设备全局布局优化研究。设备位置发生改变时，各物流接口的空间坐标随之平移，进而引起各任务组物流长度的变化。优化的核心思想是合理调整车间内各设备的摆放位置，在满足布局约束条件的前提下，使车间日均加权搬运距离达到最小，以此降低车间物流运输成本。
	
	优化的决策变量为每台设备左下角的平面坐标。布局过程中存在三项硬性约束：第一，所有设备必须完全置于车间边界以内，不能出现设备部分或整体超出车间范围的情况；第二，车间被离散为多个网格单元，每个网格内的设备占用面积占比不能超过附件2给定的阈值，防止局部区域设备分布过于拥挤；第三，各设备实体之间不能发生重叠干涉，保证设备之间具备合理的空间位置关系。
	
	该问题属于带多约束的连续型布局优化问题，待优化的设备数量多、变量维度高，同时约束之间相互耦合，是典型的NP-难问题，不存在简单的解析求解方法，需要采用智能优化算法进行迭代寻优\cite{sun2025slp}。
	
	完成优化计算后，需要输出多项结果用于方案评价：给出优化后的日均加权搬运距离目标值，对比原始布局计算改善比例；输出每台设备优化后的位置坐标；绘制车间布局可视化图与网格占用率分布图，校验全部网格是否满足占用率约束。若选用随机型智能算法，则需要明确算法参数，并通过多次独立运行测试结果的稳定性。
	
	\subsection{问题三分析}
	
	对于问题三，本题研究车间网格层面的AGV物流拥堵评估问题。题目给出矩形扩散式物流密度基准模型：对每个物流任务组，利用物流接口的最小外接矩形，假设物流流量在矩形内部均匀分布，依据网格与外接矩形的重叠面积占比计算每个任务组对网格的流量贡献，叠加后得到网格物流密度。
	
	该基准模型仅依靠外接矩形的重叠面积分配流量，忽略AGV的运动规则、真实运输路径、任务流量差异以及设备障碍物对通行空间的限制\cite{wang2026transport}，会造成拥堵评估结果与车间实际运行情况存在偏差。
	
	问题分为四项任务：第一，分析原有矩形扩散模型存在的缺陷；第二，建立改进的网格拥堵评估模型，需要综合考虑AGV仅沿水平、竖直方向移动（曼哈顿路径）、各任务组运输强度不同、存在多条可行路径、设备占据空间阻碍通行这四类因素；第三，将改进模型应用于问题二输出的最优布局，计算每个网格的拥堵强度；第四，绘制网格拥堵热力图，定位拥堵严重区域并分析成因。
	
	题目说明不需要做逐点精细路径规划，可以采用近似、采样、概率路由等方式估计路径经过网格的概率，同时需要说明模型的计算复杂度与近似带来的误差来源。该模型的输出可以用来评价布局方案的通行性能，弥补问题二仅以总搬运距离为优化目标、未考虑局部拥堵的不足。
	
	\subsection{问题四分析}
	
	对于问题四，在问题二全局布局优化、问题三拥堵评估模型的基础上，构建考虑任务需求波动的多目标稳健布局模型。在实际生产场景中，订单结构变化会造成各物流任务组的搬运强度发生波动：每个任务组实际强度会在区间\([0.85f_k,1.15f_k]\)内独立变化，不再固定为附件 1 给出的基准值\(f_k\)\cite{wang2026}。
	
	布局设计需要同时兼顾三项优化目标：一是保持较小的日均加权搬运距离，保障车间物流运输效率；二是控制网格拥堵强度，降低局部区域发生AGV拥堵的风险；三是控制设备改造调整成本，避免设备位置相较于原始布局移动距离过大，减少现场改造的经济成本。同时模型仍需保留车间边界、网格设备占用率、设备互不重叠等基础约束条件。
	
	该问题属于带不确定性的多目标约束优化问题，多个优化目标之间存在相互冲突：缩短搬运距离可能会使物流通道集中、加剧局部拥堵；为缓解拥堵大幅移动设备又会带来更高的改造费用。因此不存在唯一的最优解，需要求解帕累托最优解集，并从中选取一个适合工程落地的推荐布局方案。
	
	完成模型求解后，需要将推荐布局与问题二得到的布局结果开展对比分析：在基准任务强度下评估运输效率、拥堵水平、调整成本；检验在任务强度随机波动、不利工况下布局方案的稳健性能；分析多个目标之间的权衡关系；同时模型需要支持输出设备调整的优先顺序，以满足仅改造部分设备的实际需求。
	\section{模型假设}
	\begin{itemize}
		\item 设备摆放方向固定，不可旋转；
		\item 车间区域为二维矩形区域 $[0,W]\times [0,H]$；
		\item 物料搬运距离采用曼哈顿距离计算：$d = |x_1-x_2|+|y_1-y_2|$。
		\item 设备为轴对齐矩形，长宽尺寸固定，外形不发生改变；
		\item 物流接口相对于所属设备左下角的局部位置保持不变，设备平移时接口坐标同步平移；
		\item AGV沿水平、竖直方向移动，仅允许曼哈顿路径，不存在斜向通行；
		\item 设备本体占据的空间为障碍物，AGV不可穿过设备区域；
		\item 网格为尺寸均匀的正方形单元；
		\item 各任务组的任务强度相互独立，波动范围为 $[0.85 f_k, 1.15 f_k]$；
		\item 不考虑车间内除设备以外的其他障碍物；
		\item 计算拥堵强度时，允许采用路径采样近似估计路径经过网格的概率，不做精细的实时动态路径规划。
	\end{itemize}

	\section{问题一模型的建立与求解}
	\subsection{建模目标}
	对第 $k$ 个物流任务组，已知其 $m_{k}$ 个接口坐标、RBE和日均搬运批次 $f_{k}$，估计真实最短连通长度 $\hat{L}_{k}$，使其尽可能接近附件中的RML。日均加权搬运距离计算公式为
	\[
	D=\frac{\sum_{k=1}^{213} f_{k} \hat{L}_{k}}{\sum_{k=1}^{213} f_{k}} .
	\]
	其中，$\sum\limits _{k=1}^{213} f_{k}=4736$。
	
	\subsection{特征构造}
	设第 $k$ 个任务组的接口坐标集合为
	\[
	P_{k}=\left\{\left(x_{i}, y_{i}\right), i=1, \dots, m_{k}\right\}.
	\]
	
	\subsection{RBE指标}
	\[
	R_{k}=\left(x_{\text{max}}-x_{\text{min}}\right)+\left(y_{\text{max}}-y_{\text{min}}\right) .
	\]
	
	\subsection{包络矩形形状特征}
	记
	\[
	\Delta x=x_{\text{max}}-x_{\text{min}},\quad \Delta y=y_{\text{max}}-y_{\text{min}} .
	\]
	矩形形状指标定义为
	\[
	a_{k}=\frac{\min (\Delta x, \Delta y)}{\max (\Delta x, \Delta y)} .
	\]
	$a_{k}$ 越接近1，代表包络矩形越接近正方形。

	\subsection{接口空间分散程度特征}
	平均两两曼哈顿距离：
	\[
	p_{k}=\frac{2}{m_{k}\left(m_{k}-1\right) R_{k}} \sum_{i<j}\left(\left|x_{i}-x_{j}\right|+\left|y_{i}-y_{j}\right|\right) .
	\]
	
	接口最大间距：
	\[
	q_{k}=\frac{\max _{i, j}\left(\left|x_{i}-x_{j}\right|+\left|y_{i}-y_{j}\right|\right)}{R_{k}} .
	\]

	\subsection{连通复杂度特征}
	构建接口点之间曼哈顿距离的完全图，求解其最小生成树总长度 $T_{k}$，定义连通复杂度指标
	\[
	s_{k}=\frac{T_{k}}{R_{k}}.
	\]
	$s_{k}$ 数值越大，表明接口点越难以通过简单路径完成连通。
	
	\subsection{快速回归估计模型}
	为保证预测连通长度不小于RBE下界，采用乘法修正形式
	\[
	\hat{L}_{k}=R_{k} \max \left(1, \hat{r}_{k}\right) .
	\]
	式中
	\begin{align*}
		\hat{r}_{k}=& \beta_{0}+\beta_{1} m_{k}+\beta_{2} \ln m_{k}+\beta_{3} a_{k}+\beta_{4} p_{k}+\beta_{5} q_{k}+\beta_{6} s_{k} \\
		& +\beta_{7} m_{k} a_{k}+\beta_{8} m_{k} p_{k}+\beta_{9} m_{k} q_{k}+\beta_{10} m_{k} s_{k} \\
		& +\beta_{11}\left(\ln m_{k}\right) p_{k}+\beta_{12}\left(\ln m_{k}\right) q_{k}+\beta_{13}\left(\ln m_{k}\right) s_{k}.
	\end{align*}
	
	基于213组物流任务样本开展岭回归，得到回归系数：
	\begin{align*}
		\beta = (&0.888464,-0.039456,-0.010663,-0.002314, \\
		&0.012688,0.009744,0.013765,0.003564, \\
		&0.022362,0.002914,0.045058,0.007021, \\
		&0.002808,0.015429).
	\end{align*}
	

	模型输入特征涵盖接口数量、接口空间分散程度、包络矩形长宽形态、接口连通复杂度，同时引入接口数量与空间特征的交互项。

	\subsection{带上下界几何校正的RML预测器}
	在问题一预测模型基础上，建议采用有上下界的几何校正预测器，缓解普通回归模型在新布局场景下的预测失真问题：
	\[
	\hat{L}_{k}=b_{k}+\left(t_{k}-b_{k}\right) \sigma\left(\beta_{0}+\beta^{\top} z_{k}\right),
	\]
	式中，$b_{k}=(\max x-\min x)+(\max y-\min y)$为RBE下界；$t_k$为任务接口的曼哈顿最小生成树长度，作为RML上界；$\sigma(\cdot)$为Logistic函数；特征$z_k$选取接口数量、包围盒长宽比、接口两两平均曼哈顿距离、离散度等。该形式天然满足约束
	\[
	\text{RBE}_{k} \leq \hat{L}_{k} \leq \text{MST}_{k}.
	\]
	利用附件213组$(\text{RBE},\text{RML})$样本训练系数$\beta$，采用MAE、RMSE、$R^2$作为评价指标，并与直接使用RBE的预测结果进行对比。

	\subsection{优化目标函数}
	布局优化目标为最小化日均加权搬运距离：
	\[
	\min D(X)=\frac{\sum_{k \in K} f_{k} \hat{L}_{k}(X)}{\sum_{k \in K} f_{k}}.
	\]
	等价于最小化日加权总物流长度$\sum_{k} f_{k}\hat{L}_{k}$。定义优化改善率
	\[
	\eta=\frac{D_{0}-D^{*}}{D_{0}} \times 100\%,
	\]
	其中$D^{*}$为优化后日均加权搬运距离。

	\subsection{模型约束条件}
	\begin{enumerate}
	\item 设备边界约束：设备不可超出车间边界
	\[
	0 \leq x_{i} \leq 38080-w_{i},\quad 0 \leq y_{i} \leq 37800-h_{i}.
	\]
	
	\item 设备不重叠约束：对任意$i<j$，满足
	\[
	x_{i}+w_{i} \leq x_{j} \vee x_{j}+w_{j} \leq x_{i} \vee y_{i}+h_{i} \leq y_{j} \vee y_{j}+h_{j} \leq y_{i}.
	\]
	该逻辑条件可借助Big‑M与0‑1变量实现线性化；若需要预留AGV通道，可将设备宽高替换为$w_{i}+2s_i$、$h_{i}+2s_i$。
	
	\item 网格占用率约束：网格$g$面积$A_g=595\times 630$，设备与网格相交面积为$A_{ig}$，要求
	\[
	\sum_{i \in I} A_{ig}(x_i,y_i) \leq 0.9 A_g,\quad \forall g\in G.
	\]
	矩形相交面积采用正部算子精确计算：
	\[
	A_{ig}=\big[\min\left(x_{i}+w_{i},\overline{x}_{g}\right)-\max\left(x_{i},\underline{x}_{g}\right)\big]_{+}\big[\min\left(y_{i}+h_{i},\overline{y}_{g}\right)-\max\left(y_{i},\underline{y}_{g}\right)\big]_{+}.
	\]
\end{enumerate}


	该模型将RML预测器通过接口偏移坐标与布局决策变量耦合，同时实现物流距离最小化、设备边界约束、防重叠、网格占用率控制，满足问题二对任务物流长度重新计算的建模要求。

	
	\section{问题三模型的建立与求解}
	\subsection{原始矩形扩散模型缺陷}
	矩形扩散模型将物流频次 $f_k$ 按照任务组外接矩形面积做均分处理，该建模方式与AGV实际运行特征存在明显偏差\cite{chen2025}，主要问题如下：
	\begin{itemize}
		\item AGV沿水平、竖直通道行驶，交通流属于线路径径流，并非矩形区域内均匀面状扩散；
		\item 矩形内部存在设备占据的不可通行区域，模型依旧向该区域分配流量；
		\item 忽略任务强度、接口物流关联以及多接口任务的连通结构；
		\item 未考虑多最短路径共存、路径选择概率与交叉通道汇流效应；
		\item 仅统计流量大小，不区分通道通行能力差异，无法区分“流量大”和“通行容量小”两类拥堵成因。
	\end{itemize}
	
	\subsection{改进模型构建}
	将车间离散划分为 $64\times 60$ 的网格单元，记网格集合为 $\mathcal{G}$，设备实体矩形集合为 $R_i$。
	
	\subsubsection{网格通行能力}
	网格 $g$ 的可通行面积比例：
	\[
	\phi_g=\frac{A_g-\left|G_g \cap\left(\bigcup_i R_i\right)\right|}{A_g}.
	\]
	设置通行阈值 $\phi_{\min}$，当满足 $\phi_g<\phi_{\min}$ 时将网格视作障碍；其余网格作为图节点。相邻且共享边的可通行网格之间构建网络图边 $e=(g,h)$。
	
	若已知AGV车宽、行驶速度、安全间距参数，边容量定义：
	\[
	C_{gh}=\frac{T v}{s}\left\lfloor\frac{b_{gh}}{w_{\text{AGV}}+d_{\text{safe}}}\right\rfloor,
	\]
	式中：$b_{gh}$ 为相邻网格有效通道宽度，$T$ 为日工作时长，$v$ 为AGV行驶速度，$s$ 为同车间距。本题附件缺少上述物理参数，采用相对容量：
	\[
	\widetilde{C}_{gh}=\min(\phi_g,\phi_h).
	\]
	
	\subsubsection{多接口任务转换为OD需求}
	设任务组 $k$ 的接口集合为 $P_k$，日均搬运批次为 $f_k$。
	在无确定工艺先后顺序条件下，对任务接口构建曼哈顿最小生成树 $T_k$；树上每条边 $(a,b)$ 对应一段物流连通关系，分配物流需求：
	\[
	q_{kab}=f_k,\quad (a,b)\in T_k.
	\]
	任务组总运输规模等价于“搬运批次 × 连通网络总长度”。若后续获取真实工艺顺序，只需将最小生成树边替换为实际OD点对。
	
	\subsubsection{概率最短路径流量分配}
	对每一OD点对 $(a,b)$，在障碍约束网格图中求解全部曼哈顿最短路径集合 $\mathcal{P}_{kab}^{*}$。
	
	基础等概率路径选择方案：
	\[
	\pi_{kabp}=\frac{1}{|\mathcal{P}_{kab}^{*}|},\quad p\in \mathcal{P}_{kab}^{*}.
	\]
	
	为体现AGV避堵绕行行为，采用Logit路径选择模型：
	\[
	\pi_{kabp}=\frac{\exp\left[-\theta c_p\right]}{\sum_{r\in \mathcal{P}_{kab}}\exp\left[-\theta c_r\right]},
	\]
	\[
	c_p=L_p+\gamma \sum_{e\in p}\eta_e,
	\]
	$L_p$ 代表路径长度，$\eta_e$ 为边拥堵程度。采用逐次平均迭代法更新各路径流量直至收敛。
	
	\subsubsection{网格拥堵强度指标}
	边交通流量：
	\[
	F_{gh}=\sum_{k}\sum_{(a,b)\in T_k}\sum_{p\in \mathcal{P}_{kab}} q_{kab}\pi_{kabp}\boldsymbol{1}(e_{gh}\in p).
	\]
	
	网格 $g$ 拥堵强度：
	\[
	\eta_g=\frac{\frac12\sum_{h:(g,h)\in E} F_{gh}}{\frac12\sum_{h:(g,h)\in E} C_{gh}+\varepsilon}.
	\]
	$\eta_g>1$ 代表区域物流需求超出通行能力。缺少AGV物理参数时，使用相对拥堵指标用于热点识别与方案对比：
	\[
	I_g=\frac{F_g}{\phi_g+\varepsilon},
	\]
	$\varepsilon$ 为极小正数，用于防止分母为0。

	\begin{enumerate}
		\item 读取问题二设备优化坐标，更新全部接口绝对坐标；
		\item 计算每个网格设备覆盖面积与可通行面积比例 $\phi_g$；
		\item 构建可通行网格网络图，校验全部任务接口的连通性；
		\item 对每个物流任务组构建曼哈顿最小生成树；
		\item 采用BFS算法求解最短路径距离与路径集合，计算各最短路径经过网格的概率；

\section{问题四模型的建立与求解}
针对车间物流需求存在波动的现实场景，基于213组物流任务与222台设备构建多目标稳健布局优化模型，在物流效率、AGV拥堵风险、设备改造成本、局部设备密度之间取得权衡，输出具备抗扰动能力的可落地布局方案。

\subsection{网格约束处理}
原始 $64\times60$ 微网格单元尺寸为 $595\times 630$，设备高度为1800，大于两倍微网格高度。若直接采用单微网格相交面积约束占用率不大于0.9，由于设备会完整覆盖部分微网格，该约束不存在可行解，该现象由算例数据尺度本身造成，并非算法缺陷。

为保留“避免局部设备过密、保障AGV通行”的工程意图，将 $4\times4$ 个原始微网格合并形成运营分区，分区尺寸为 $2380\times 2520$，占用率阈值仍取0.9；设备带之间预留720单位宽度的AGV横向通行通道。本文推荐布局的最大运营分区占用率为0.7143，全部分区均满足占用率约束。

\subsection{多目标稳健数学模型}
记设备集合为 $I$，物流任务集合为 $K$，运营分区集合为 $G$，需求情景集合为 $S$。设备 $i$ 的宽、高为 $(w_i,h_i)$，原始左下角坐标为 $(x_i^0,y_i^0)$，优化后决策坐标为 $(x_i,y_i)$。任务 $k$ 的基准日均搬运需求为 $f_k$，考虑需求波动：
\[
f_{ks}=f_k(1+\xi_{ks}),\quad \xi_{ks}\in[-0.15,0.15],\; s\in S.
\]
采用拉丁超立方抽样生成情景集合 $S$，额外构造全部任务同时增加15\%的箱式最坏情景。接口坐标由设备坐标偏移得到：
\[
p_{ia}=(x_i+\Delta x_{ia},\; y_i+\Delta y_{ia}).
\]
任务连通长度复用问题一建立的端口组连通长度预测模型 $\widehat L_k(X)$。

\subsubsection{优化目标}
\begin{enumerate}
	\item \textbf{稳健加权运输距离}
	情景 $s$ 下加权平均运输距离：
	\[
	D_s(X)=\frac{\sum_{k\in K} f_{ks} \widehat L_k(X)}{\sum_{k\in K} f_{ks}}.
	\]
	采用“情景期望+CVaR条件风险值”度量稳健运输目标，置信水平 $\alpha=0.95$：
	\[
	F_1(X)=\frac{1}{|S|}\sum_{s\in S} D_s(X)+\lambda_D \text{CVaR}_\alpha\big(D_s(X)\big).
	\]
	
	\item \textbf{AGV拥堵强度稳健目标}
	$r_{kes}$ 为情景 $s$ 任务 $k$ 分配给可选路径 $e$ 的流量比例，满足 $\sum\limits_{e\in E_k} r_{kes}=1$。$a_{keg}(X)$ 为0‑1指示变量，代表路径 $e$ 是否经过分区 $g$。分区交通负荷：
	\[
	q_{gs}(X)=\sum_{k\in K}\sum_{e\in E_k} f_{ks} r_{kes} a_{keg}(X).
	\]
	情景最大拥堵强度 $Q_s(X)=\max\limits_{g\in G} q_{gs}(X)$。拥堵稳健目标：
	\[
	F_2(X)=\frac{1}{|S|}\sum_{s\in S} Q_s(X)+\lambda_Q \text{CVaR}_\alpha\big(Q_s(X)\big).
	\]
	
	\item \textbf{设备迁移成本}
	设备迁移欧氏距离：
	\[
	d_i=\sqrt{(x_i-x_i^0)^2+(y_i-y_i^0)^2}.
	\]
	$z_i\in\{0,1\}$ 标记设备是否迁移；$c_i$ 为单位距离迁移成本，$h_i$ 为单次迁移停机拆装固定成本。迁移总目标：
	\[
	F_3(X)=\sum_{i\in I}\big(c_i d_i+h_i z_i\big),
	\]
	配套关联约束：$d_i\le M z_i$。
	
	\item \textbf{局部占用密度目标}
	$A_g$ 为运营分区面积，$A_{ig}(X)$ 为设备与分区相交面积，分区占用率：
	\[
	\rho_g(X)=\frac{\sum_{i\in I} A_{ig}(X)}{A_g}.
	\]
	可将最大分区占用密度作为目标：$F_4(X)=\max\limits_{g\in G}\rho_g(X)$；也可转化硬约束：
	\[
	\rho_g(X)\le \rho_{\max},\quad \forall g\in G,\quad \rho_{\max}=0.9.
	\]
\end{enumerate}

\subsubsection{可行性约束}
设备车间边界约束：
\[
0\le x_i \le W-w_i,\quad 0\le y_i \le H-h_i,\quad \forall i\in I.
\]
采用Big‑M方法配合四组0‑1二元变量，实现设备两两不重叠约束；同时包含路径流量分配约束、需求波动情景约束。完整模型为多目标极小化：
\[
\min_{X}\; \big(F_1(X),F_2(X),F_3(X),F_4(X)\big).
\]
为得到单一推荐方案，采用归一化加权法：
\[
\min\; 0.40\widetilde{F}_1+0.30\widetilde{F}_2+0.20\widetilde{F}_3+0.10\widetilde{F}_4.
\]
权重设置体现优先级：物流距离优先，其次拥堵风险，兼顾迁移实施成本与局部通行冗余。

\subsection{目标权衡关系与工程实施建议}

现场实施建议：首先完成设备带划分、AGV横向通道与车间边界标识；分三批顺序迁移设备：低耦合设备Mach145--222，中耦合设备Mach17--144，最后迁移高耦合设备Mach1--16；每一批设备迁移完成后复测通道拥堵负荷。设备带状布局有利于保持接口坐标可控，降低生产线停线风险。设备优化后的左下角坐标详见文档附录。
	
	\section{灵敏度分析}
	为检验推荐稳健布局对任务需求波动、目标权重与空间约束的适应能力，围绕需求波动幅度、目标权重和分区占用率阈值开展灵敏度分析。评价指标包含加权平均运输距离、最大分区通道负荷、最坏情景最大负荷、设备迁移距离以及最大运营分区占用率。
	
	\subsection{任务需求波动幅度的灵敏度}
	以各任务需求在基准值附近独立波动 $\pm 15\%$ 为分析基准，采用300组拉丁超立方抽样情景，同时设置全部任务需求同时上浮15\%的箱式最坏情景。推荐稳健布局基准需求下最大分区通道负荷为291.0；随机扰动条件下指标95\%分位为309.80，较基准值增加6.46\%；箱式最坏情景最大负荷为334.65，较基准值增加15.00\%。
	
	该结果与模型线性流量叠加特性保持一致：全部任务需求按比例 $1+\delta$ 变化，路径分配无显著改变时，满足：
	\[
	Q_{\max}(\delta)\approx Q_{\max}(0)(1+\delta).
	\]
	据此推算，需求同时上浮10\%，最大负荷约为320.10；上浮20\%，最大负荷约为349.20。最大通道负荷对整体需求强度近似线性敏感，需求波动是拥堵风险的首要外部影响因素。
	
	加权平均运输距离定义：
	\[
	D_{s}=\frac{\sum_{k\in K} f_{ks} L_{k}(X)}{\sum_{k\in K} f_{ks}}.
	\]
	当所有任务强度同比例缩放，分子分母同步变化，平均运输距离理论上保持不变；仅当不同任务需求发生非同步变化，运输距离才产生波动。仿真得到推荐方案运输距离95\%分位为11817.42，相比基准值11706.47仅上升0.95\%，布局面对任务结构随机扰动稳定性较好。

	\subsection{分区占用率阈值的灵敏度}
	推荐布局最大运营分区占用率为0.7143，低于约束阈值0.9，预留0.1857裕量。当占用率上限 $\rho_{\max}\ge 0.7143$，现有布局满足约束，阈值小幅放宽不会改变可行性；若 $\rho_{\max}<0.7143$，当前解失效，需要重新优化设备排布或扩充通道面积。
	
	选取 $\rho_{\max}=0.70、0.72、0.75、0.80、0.85、0.90$ 开展单因素仿真。阈值低于0.72时可行解空间被压缩，迁移距离、运输距离同步上升；阈值大于0.85之后，占用率约束对当前方案几乎不起作用，但设备密度过高会挤压AGV通行冗余，加剧局部拥堵。
	
	需要注意，直接在原始 $64\times60$ 微网格施加0.9占用率约束不存在可行解。占用率灵敏度分析必须基于$4\times4$微网格合并得到的运营分区开展，防止网格尺度差异带来错误结论。
	
	\subsection{灵敏度分析结论}
	推荐稳健布局对任务结构随机扰动具备较强稳定性。在需求 $\pm15\%$ 扰动条件下，运输距离95\%分位仅增加0.95\%；最坏情景最大负荷依旧低于距离优先方案6.58\%。模型对整体任务总强度高度敏感，最大通道负荷随需求近似线性增长；占用率阈值存在明显可行临界值，0.7143为本方案关键临界点。工程实际中重点监控高负荷通道与订单总规模，结合现场改造条件调整拥堵、迁移成本权重。
	
	
	\section{模型的优缺点}
	\subsection{模型优点}
	\begin{enumerate}
		\item 构建了“快速物流评估—全局布局优化—网格拥堵评估—任务波动稳健布局”完整研究链路，针对柔性制造车间工艺切换频繁、物流拥堵、任务强度波动三大痛点，同时兼顾搬运距离、设备聚集程度、AGV拥堵、布局抗扰动、改造成本多重现实目标，区别于传统仅最小化搬运距离的单目标布局模型。
		\item 物流快速评估精度高且兼顾计算速度。基于岭回归引入接口数量、包络矩形形态、接口离散度、连通复杂度以及交互特征，对传统RBE矩形包络指标做校正；7折交叉验证表明MAE、RMSE、MAPE均大幅下降，$R^2$达到0.99599；既保留快速计算能力，又解决RBE对多接口复杂任务组系统性低估RML真实物流长度的缺陷，可嵌入布局迭代优化，避免反复求解最小生成树带来的巨大算力开销。
		\item 多约束数学处理严谨，工程可落地。使用Big‑M法线性化处理设备不重叠逻辑约束；引入网格占用率约束防止设备局部扎堆；针对原始微网格约束无解的尺度问题，提出\textbf{4$\times$4合并运营分区}方案；接口坐标跟随设备平移，完整实现设备位置与物流距离的耦合建模，输出设备坐标、占用率校验、可视化的全套结果，支持多次运行分析算法稳定性。
		\item 改进拥堵评估模型还原AGV运行机理。摒弃传统矩形面扩散流量分配，构建网格通行网络图；结合曼哈顿最小生成树拆解多接口任务为OD点对；采用BFS求最短路径、Logit概率路径选择，考虑AGV横纵移动、设备障碍物、多路径分流汇流效应；可输出拥堵热力图定位热点，弥补仅以搬运距离优化带来“距离短但局部拥堵严重”的缺陷。
		\item 引入不确定性，实现稳健布局优化。采用拉丁超立方抽样生成任务波动情景，利用CVaR条件风险价值度量拥堵与运输距离尾部风险；同时优化物流效率、拥堵风险、设备搬迁成本；支持帕累托权衡分析，可输出设备迁移优先级，支持“只改造部分设备”的边生产边改造场景，给出带状设备带+标准化AGV通道的工程实施方案。
		\item 完备的灵敏度分析。分别针对任务波动幅度、多目标权重、分区占用率阈值开展灵敏度仿真；明确各目标之间的冲突权衡关系，给出新建车间、大修改造、不停产改造不同场景的权重设置建议，方便现场人员调整参数得到适配方案。
	\end{enumerate}
	
	\subsection{模型缺点}
	\begin{enumerate}
		\item 快速评估模型存在数据依赖。岭回归预测效果高度依赖样本集，当出现接口数量极大、接口空间分布形态完全异于训练样本的任务组时，预测会产生外推误差；虽然增加上下界几何校正，但本质仍属于数据驱动回归，不是严格解析推导模型。
		\item 计算规模大，求解耗时较高。问题二、四属于高维NP‑难带约束组合优化问题；设备数量222台，决策变量维度高，叠加网格占用率约束、情景抽样、CVaR风险计算，计算开销大；在设备数量进一步增加时，求解时间会显著上升，对硬件算力有一定要求。
		\item 拥堵评估为静态概率近似，非实时动态仿真。拥堵模型基于静态任务流量+概率路径选择，没有模拟AGV动态排队、车辆冲突、实时避障；没有引入AGV车辆数量、行驶速度、加减速、安全间距等完整物理参数，输出是\textbf{相对拥堵指标}，只能用于方案横向对比，不能直接输出精确AGV队列长度、等待时间等仿真指标。
		\item 部分参数需要人工经验设定。如通行阈值$\phi_{\mathrm{min}}$、CVaR置信水平、多目标归一化权重、迁移固定成本参数没有统一理论最优值，需要结合车间经验调整；权重设置会直接改变最终布局方案，主观因素会对结果产生影响。
		\item 模型做了若干理想化假设。假设设备不可旋转，没有考虑设备旋转带来的布局优化潜力；只考虑曼哈顿路径，忽略斜向特殊通道；不考虑设备之外障碍物；任务波动采用独立区间扰动，未考虑不同任务组之间的强关联耦合波动场景。
		\item 网格尺度会影响约束可行性。原始微网格尺度下直接施加占用率上限不存在可行解，必须合并为运营分区；网格划分粒度选择会改变占用率、拥堵强度结果，若网格设置不合理，会造成约束校验与拥堵评估失真，需要人工选择合适网格粒度。
	\end{enumerate}

	def comb_safe(n: int, k: int) -> int:
	if n < 0 or k < 0 or k > n:
	return 0
	if k == 0 or k == n:
	return 1
	k = min(k, n - k)
	res = 1
	for i in range(1, k + 1):
	res = res * (n - k + i) // i
	return res
	
	def rect_intersection_area(ax, ay, aw, ah, bx, by, bw, bh):
	x_overlap = max(0, min(ax + aw, bx + bw) - max(ax, bx))
	y_overlap = max(0, min(ay + ah, by + bh) - max(ay, by))
	return x_overlap * y_overlap

	param_line_idx = None
	for idx, line in enumerate(lines):
	nums = re.findall(r"-?\d+\.?\d*", line)
	if len(nums) >= 5:
	try:
	float(nums[0]); float(nums[1]); int(float(nums[2])); int(float(nums[3])); float(nums[4])
	param_line_idx = idx
	break
	except Exception:
	continue
	if param_line_idx is None:
	raise ValueError("未找到车间参数行")
	
	nums = re.findall(r"-?\d+\.?\d*", lines[param_line_idx])
	W = float(nums[0]); H = float(nums[1])
	grid_nx = int(float(nums[2])); grid_ny = int(float(nums[3])); rho_max = float(nums[4])

	continue
	m = re.match(r"([^,]+),\(([^)]+)\),([^,]+),([^,]+),\(([^)]+)\),\((.*)\)$", line)
	if not m:
	continue
	name = m.group(1).strip()
	x_str, y_str = m.group(2).split(",")
	x = float(x_str); y = float(y_str)
	w = float(m.group(3)); h = float(m.group(4))
	iface_str = m.group(5)
	offsets_str = m.group(6)
	iface_names = [s.strip() for s in iface_str.split(",") if s.strip()]
	offset_pairs = re.findall(r"\(([^)]+)\)", offsets_str)

		"name": name,
		"x": x, "y": y,
		"w": w, "h": h,
		"ports": ports,
		"port_names": iface_names,
	})
	return W, H, grid_nx, grid_ny, rho_max, devices

	# ===================== Q1 RML预测模型 =====================
	def manhattan_mst(points):
	"""计算一组点的曼哈顿最小生成树长度（Prim 算法，任务组接口数≤7，速度很快）。"""
	n = len(points)
	if n <= 1:
	return 0.0
	used = [False] * n
	used[0] = True
	total = 0.0
	for _ in range(n - 1):
	best = None
	for i in range(n):
	if not used[i]:
	continue
	for j in range(n):
	if used[j]:
	continue
	d = abs(points[i][0] - points[j][0]) + abs(points[i][1] - points[j][1])
	if best is None or d < best[0]:
	best = (d, i, j)
	total += best[0]
	used[best[2]] = True
	return total
	
	class RMLPredictor:
	"""
	混合快速评估模型（在附件1数据上 MAPE≈0.5\%，优于直接使用 RBE 的≈1.9\%）：
	- 接口数 n≤3：RML 与 RBE 严格相等（矩形包络即为最短连接），直接取 RBE；
	- 接口数 n≥4：RML 介于 RBE（包络下界）与曼哈顿最小生成树 MST（覆盖上界）之间，
	取  RML ≈ RBE + α·(MST − RBE)，其中 α 由最小二乘在训练数据上标定。
	"""
	def __init__(self):
	self.alpha = 0.55
	
	def train(self, task_groups):
	num = 0.0
	den = 0.0
	for tg in task_groups:
	pts = [(p[2], p[3]) for p in tg["ports"]]
	e = manhattan_mst(pts) - tg["rbe"]
	d = tg["rml"] - tg["rbe"]
	if e <= 1e-9:
	continue
	num += e * d
	den += e * e
	if den > 1e-12:
	self.alpha = num / den
	
	def predict(self, task_group):
	pts = [(p[2], p[3]) for p in task_group["ports"]]
	n = len(pts)
	rbe = task_group["rbe"]
	if n <= 3:
	return float(rbe)
	mst = manhattan_mst(pts)
	return float(rbe + self.alpha * max(0.0, mst - rbe))
	
	def q1_error_metrics(task_groups, predictor):
	"""计算模型 MAPE 并与直接使用 RBE 对比；同时给出按接口数分组误差。"""
	mape_pred, mape_rbe = [], []
	groups = {}
	for tg in task_groups:
	if tg["rml"] <= 0:
	continue
	p = predictor.predict(tg)
	mape_pred.append(abs(p - tg["rml"]) / tg["rml"])
	mape_rbe.append(abs(tg["rbe"] - tg["rml"]) / tg["rml"])
	n = len(tg["ports"])
	groups.setdefault(n, []).append(abs(p - tg["rml"]) / tg["rml"])
	mape_pred = np.array(mape_pred); mape_rbe = np.array(mape_rbe)
	print("\n[Q1 模型精度评估]")
	print(f"  模型估计 RML 的 MAPE = {np.mean(mape_pred)*100:.2f}\%  (MaxAPE={np.max(mape_pred)*100:.2f}\%)")
	print(f"  直接使用 RBE 的 MAPE = {np.mean(mape_rbe)*100:.2f}\%  (MaxAPE={np.max(mape_rbe)*100:.2f}\%)")
	for n in sorted(groups):
	arr = np.array(groups[n])
	print(f"    接口数 n={n}: 样本量={len(arr)}, MAPE={np.mean(arr)*100:.2f}\%")
	return float(np.mean(mape_pred)), float(np.mean(mape_rbe))
	
	# ===================== Q3 拥堵评估 =====================
	def random_monotone_path(sx, sy, ex, ey):
	"""生成一条从 (sx,sy) 到 (ex,ey) 的随机曼哈顿单调路径（只朝目标方向移动）。"""
	path = [(sx, sy)]
	cx, cy = sx, sy
	while cx != ex or cy != ey:
	moves = []
	if cx < ex: moves.append((1, 0))
	if cx > ex: moves.append((-1, 0))
	if cy < ey: moves.append((0, 1))
	if cy > ey: moves.append((0, -1))
	if not moves:
	break
	dxs, dys = random.choice(moves)
	cx += dxs; cy += dys
	path.append((cx, cy))
	return path
	
	def compute_grid_congestion(devices, task_groups, W, H, grid_nx, grid_ny,
	num_path_samples=300, return_per_task=False):
	"""
	改进的网格物流拥堵评估：
	- 设备占据的网格视为不可通行（体现设备对通行空间的影响）；
	- 对每个任务段，按曼哈顿方向随机采样 num_path_samples 条最短路径，
	统计各网格被路径经过的次数，再按任务强度加权；
	- 若所有采样均被阻塞，则退化为全网格的解析概率（组合数枚举/随机单调路径）。
	"""
	cell_w = W / grid_nx
	cell_h = H / grid_ny
	occupied = np.zeros((grid_ny, grid_nx), dtype=bool)
	for dev in devices:
	x0 = int(dev["x"] // cell_w)
	y0 = int(dev["y"] // cell_h)
	x1 = int((dev["x"] + dev["w"] - 1e-9) // cell_w)
	y1 = int((dev["y"] + dev["h"] - 1e-9) // cell_h)
	x0 = max(0, min(grid_nx - 1, x0))
	x1 = max(0, min(grid_nx - 1, x1))
	y0 = max(0, min(grid_ny - 1, y0))
	y1 = max(0, min(grid_ny - 1, y1))
	occupied[y0:y1 + 1, x0:x1 + 1] = True
	
	def seg_congestion(sx, sy, ex, ey):
	sx = max(0, min(grid_nx - 1, sx)); sy = max(0, min(grid_ny - 1, sy))
	ex = max(0, min(grid_nx - 1, ex)); ey = max(0, min(grid_ny - 1, ey))
	dx, dy = ex - sx, ey - sy
	if dx == 0 and dy == 0:
	return None
	paths_count = {}
	valid_samples = 0
	attempts = 0
	max_attempts = num_path_samples * 10
	while valid_samples < num_path_samples and attempts < max_attempts:
	attempts += 1
	cur_x, cur_y = sx, sy
	path = [(cur_x, cur_y)]
	while cur_x != ex or cur_y != ey:
	possible = []
	if cur_x < ex: possible.append((1, 0))
	elif cur_x > ex: possible.append((-1, 0))
	if cur_y < ey: possible.append((0, 1))
	elif cur_y > ey: possible.append((0, -1))
	if not possible:
	break
	dx_step, dy_step = random.choice(possible)
	nx, ny = cur_x + dx_step, cur_y + dy_step
	if 0 <= nx < grid_nx and 0 <= ny < grid_ny and not occupied[ny, nx]:
	cur_x, cur_y = nx, ny
	path.append((cur_x, cur_y))
	else:
	other = [p for p in possible if p != (dx_step, dy_step)]
	if other:
	dx_step2, dy_step2 = random.choice(other)
	nx2, ny2 = cur_x + dx_step2, cur_y + dy_step2
	if 0 <= nx2 < grid_nx and 0 <= ny2 < grid_ny and not occupied[ny2, nx2]:
	cur_x, cur_y = nx2, ny2
	path.append((cur_x, cur_y))
	else:
	break
	else:
	break
	if cur_x == ex and cur_y == ey:
	valid_samples += 1
	for node in path:
	paths_count[node] = paths_count.get(node, 0) + 1
	if valid_samples == 0:
	total = comb_safe(abs(dx) + abs(dy), abs(dx))
	if total > 10000:
	for _ in range(num_path_samples):
	for node in random_monotone_path(sx, sy, ex, ey):
	paths_count[node] = paths_count.get(node, 0) + 1
	valid_samples = num_path_samples
	else:
	for gy in range(min(sy, ey), max(sy, ey) + 1):
	for gx in range(min(sx, ex), max(sx, ex) + 1):
	if abs(gx - sx) + abs(gy - sy) + abs(gx - ex) + abs(gy - ey) == abs(dx) + abs(dy):
	d1 = abs(gx - sx) + abs(gy - sy)
	d2 = abs(ex - gx) + abs(ey - gy)
	ways1 = comb_safe(d1, abs(gx - sx)) if d1 > 0 else 1
	ways2 = comb_safe(d2, abs(ex - gx)) if d2 > 0 else 1
	paths_count[(gx, gy)] = paths_count.get((gx, gy), 0) + ways1 * ways2 / total
	valid_samples = 1
	return paths_count, valid_samples
	
	per_task = []
	total_cong = np.zeros((grid_ny, grid_nx))
	for tg in task_groups:
	ports_abs = [(p[2], p[3]) for p in tg["ports"]]
	f = tg["f"]
	grid = np.zeros((grid_ny, grid_nx))
	for i in range(len(ports_abs) - 1):
	start, end = ports_abs[i], ports_abs[i + 1]
	sx = int(start[0] // cell_w); sy = int(start[1] // cell_h)
	ex = int(end[0] // cell_w); ey = int(end[1] // cell_h)
	res = seg_congestion(sx, sy, ex, ey)
	if res is None:
	continue
	paths_count, valid_samples = res
	if valid_samples > 0:
	for (gx, gy), cnt in paths_count.items():
	grid[gy, gx] += f * (cnt / valid_samples)
	per_task.append(grid)
	total_cong += grid
	if return_per_task:
	return per_task
	return total_cong

	def evaluate_layout_common(individual, devices_base, task_groups_base, W, H, grid_nx, grid_ny, rho_max):
	devices = copy.deepcopy(devices_base)
	task_groups = copy.deepcopy(task_groups_base)
	N = len(devices)
	for i in range(N):
	devices[i]["x"] = individual[2 * i]
	devices[i]["y"] = individual[2 * i + 1]
	penalty = 0.0
	for dev in devices:
	if dev["x"] < 0:
	penalty += (-dev["x"]) * 1e6
	if dev["x"] + dev["w"] > W:
	penalty += (dev["x"] + dev["w"] - W) * 1e6
	if dev["y"] < 0:
	penalty += (-dev["y"]) * 1e6
	if dev["y"] + dev["h"] > H:
	penalty += (dev["y"] + dev["h"] - H) * 1e6
	cell_w = W / grid_nx
	cell_h = H / grid_ny
	occ = np.zeros((grid_ny, grid_nx))
	for dev in devices:
	x0 = max(0, int(dev["x"] // cell_w))
	y0 = max(0, int(dev["y"] // cell_h))
	x1 = min(grid_nx - 1, int((dev["x"] + dev["w"] - 1e-9) // cell_w))
	y1 = min(grid_ny - 1, int((dev["y"] + dev["h"] - 1e-9) // cell_h))
	for gy in range(y0, y1 + 1):
	for gx in range(x0, x1 + 1):
	gx_pos = gx * cell_w
	gy_pos = gy * cell_h
	area = rect_intersection_area(dev["x"], dev["y"], dev["w"], dev["h"],
	gx_pos, gy_pos, cell_w, cell_h)
	occ[gy, gx] += area
	rho_cells = occ / (cell_w * cell_h)
	excess = np.maximum(rho_cells - rho_max, 0.0)
	penalty += float(np.sum(excess)) * 1e6
	
	for tg in task_groups:
	new_ports = []
	for port_info in tg["ports"]:
	dev_name, port_idx, _, _ = port_info
	found = False
	for dev in devices:
	if dev["name"] == dev_name:
	if port_idx >= len(dev["ports"]):
	port_idx = 0
	dx, dy = dev["ports"][port_idx]
	new_ports.append((dev_name, port_idx, dev["x"] + dx, dev["y"] + dy))
	found = True
	break
	if not found:
	new_ports.append(port_info)
	tg["ports"] = new_ports
	return devices, task_groups, penalty
	
	def grid_occupancy(devices, W, H, grid_nx, grid_ny):
	cell_w = W / grid_nx
	cell_h = H / grid_ny
	occ = np.zeros((grid_ny, grid_nx))
	for dev in devices:
	x0 = max(0, int(dev["x"] // cell_w))
	y0 = max(0, int(dev["y"] // cell_h))
	x1 = min(grid_nx - 1, int((dev["x"] + dev["w"] - 1e-9) // cell_w))
	y1 = min(grid_ny - 1, int((dev["y"] + dev["h"] - 1e-9) // cell_h))
	for gy in range(y0, y1 + 1):
	for gx in range(x0, x1 + 1):
	gx_pos = gx * cell_w
	gy_pos = gy * cell_h
	occ[gy, gx] += rect_intersection_area(dev["x"], dev["y"], dev["w"], dev["h"],
	gx_pos, gy_pos, cell_w, cell_h)
	return occ / (cell_w * cell_h)

	def evaluate_q4(individual, devices_base, task_groups_base, W, H, grid_nx, grid_ny, rho_max,
	predictor, num_samples, path_sample_cnt):
	try:
	devices, task_groups, penalty = evaluate_layout_common(
	individual, devices_base, task_groups_base, W, H, grid_nx, grid_ny, rho_max)
	if penalty > 1e-3:
	return float(penalty), float(penalty), float(penalty)
	per_task = compute_grid_congestion(devices, task_groups, W, H, grid_nx, grid_ny,
	num_path_samples=path_sample_cnt, return_per_task=True)
	D_sum = 0.0
	cong_sum = np.zeros((grid_ny, grid_nx))
	for _ in range(num_samples):
	f_actual = [tg["f"] * random.uniform(0.85, 1.15) for tg in task_groups]
	D_sample = 0.0
	cong_sample = np.zeros((grid_ny, grid_nx))
	for cgrid, fa, tg in zip(per_task, f_actual, task_groups):
	cong_sample += (fa / tg["f"]) * cgrid
	D_sample += fa * predictor.predict(tg)
	D_sum += D_sample
	cong_sum += cong_sample
	D_expected = D_sum / num_samples
	congestion_expected = float(np.max(cong_sum / num_samples))
	move_cost = 0.0
	move_cnt = 0
	for idx, dev in enumerate(devices):
	orig_x = devices_base[idx]["x"]
	orig_y = devices_base[idx]["y"]
	dx_ = abs(dev["x"] - orig_x)
	dy_ = abs(dev["y"] - orig_y)
	move_cost += math.hypot(dx_, dy_)
	if dx_ > 1 or dy_ > 1:
	move_cnt += 1
	move_cost += 0.1 * move_cnt
	return float(D_expected), float(congestion_expected), float(move_cost)
	except Exception as e:
	print(f"evaluate_q4 内部错误: {e}")
	return 1e12, 1e12, 1e12
	
	def run_q4_nsga2(W, H, grid_nx, grid_ny, rho_max, devices, task_groups, pop_size,
